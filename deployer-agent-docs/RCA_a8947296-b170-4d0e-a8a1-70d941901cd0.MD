# RCA — Redeploy failed at build_image (frontend eslint)

**Deployment:** tengoku-launcher
**Failed run:** a8947296-b170-4d0e-a8a1-70d941901cd0 (redeploy)
**Failed step:** build_image (frontend compile / CRA production build)
**Outcome:** Build failed; app NOT redeployed. The previously live run (8184a57a…) is still serving traffic at https://tengoku-launcher.emergent.host — production is unaffected.

## Root cause (proven)
The CRA production build runs eslint and fails on `frontend/src/pages/Home.js`.

Build log:
```
src/pages/Home.js
  Line 145:201:  Definition for rule '// Nexus OS (admin) ouvert par-dessus l'accueil' was not found
Failed to compile.
error Command failed with exit code 1.
```

Line 145 of `frontend/src/pages/Home.js` (confirmed by reading the source in a sandbox):
```js
useEffect(() => { const h = (e) => { sfx("select"); setUnivOpen(e.detail?.name || ""); }; window.addEventListener("nx-univers", h); return () => window.removeEventListener("nx-univers", h); }, []); // eslint-disable-line // Nexus OS (admin) ouvert par-dessus l'accueil
```

The `// eslint-disable-line` directive parses ALL text after it as a comma-separated list of rule names. Here the trailing note `// Nexus OS (admin) ouvert par-dessus l'accueil` is consumed as a (non-existent) rule name, producing the "Definition for rule '…' was not found" error, which is fatal to the production build. It is NOT a lint violation of the code itself — it is a malformed lint directive comment.

## Fix (E1 / source)
Edit `frontend/src/pages/Home.js` line 145 so the directive has no trailing free-text comment. Either:

Option A — move the note to its own line:
```js
// Nexus OS (admin) ouvert par-dessus l'accueil
useEffect(() => { const h = (e) => { sfx("select"); setUnivOpen(e.detail?.name || ""); }; window.addEventListener("nx-univers", h); return () => window.removeEventListener("nx-univers", h); }, []); // eslint-disable-line
```

Option B — use the eslint description separator `--` (text after `--` is ignored by the directive parser):
```js
}, []); // eslint-disable-line -- Nexus OS (admin) ouvert par-dessus l'accueil
```

Then redeploy. (Also worth scanning the repo for any other `// eslint-disable-line <free text>` patterns.)

## Not the cause
- Not a manifest/template issue — Dockerfile/entrypoint/nginx are unchanged from prior successful runs.
- Not secrets, tier, OOM, or DB.
