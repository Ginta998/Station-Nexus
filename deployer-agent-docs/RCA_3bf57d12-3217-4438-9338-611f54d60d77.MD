# RCA — "USF" episodes disappeared (Station Nexus / tengoku-launcher)

## Problem statement
User reports every episode of the creation **"USF"** disappeared "during the deployment" and wants them back. App: FastAPI + MongoDB. Episodes live in `creations[].episodes`.

## What I verified (production DB, read-only)

Production DB resolved server-side = **`tengoku-launcher-test_database`**.

1. **The creation exists.** "USF" is the acronym for the title **"United Sanctum Force"** — that is why a `/usf/i` title regex returns 0. It is not lost/renamed.
   - `id`: `8c46e698-97aa-4974-a196-9c2aedfa060d`
   - `updated_at`: **`2026-10-24T14:05:05.389052+00:00`**
   - `episodes`: **[]** (length 0)
   - `chapters`: **[]** (length 0)

2. **All 15 creations (titles / updated_at):** Born X Burn (2026-10-24T21:13:25), La Cité des Cieux (10-24T14:05:35), Cosmic Bunny (10-24T14:05:23), United Sanctum Force (10-24T14:05:05), S.A.M : Service Après Mort (10-24T12:14:48), Monsieur Watanabe (10-23T15:33:00), Tengoku Dojo (09-18), Born X Burn II (09-14), Liberty's Chroma : Andgi (08-02), Requiem District (08-02), Cher Père (08-02), Liberty's Chroma : Zaina (08-02), Blue Flower (08-02), Soulfreed (08-02), Katana Kid (07-23).
   - Only **2 of 15** still have any episodes: **Cosmic Bunny** and **La Cité des Cieux**. 5 of 15 still have chapters.

3. **No backup / snapshot inside this DB.** 24 collections present; none is a `creations_backup`/snapshot collection. No alternate DB_NAME is in use.

4. **The DB binding did NOT change with the deploy.** I queried the same document through the three most recent successful runs:
   - `3bf57d12…` (active), `d07bf7de…`, `dbe9125a…` — **all** resolve to db_name `tengoku-launcher-test_database`, same MONGO_URL, and return the **identical** USF doc with the **identical** `updated_at 2026-10-24T14:05:05` and empty arrays. So there was no DB swap, and a redeploy does not migrate data.

## Root cause (what the evidence shows)
This is **not deployment-caused.**
- The latest deploy (run `3bf57d12`) completed **2026-10-24T01:06:08 UTC**.
- The USF document was last written at **2026-10-24T14:05:05 UTC** — roughly **13 hours after** the deploy — and that write is where `episodes`/`chapters` are empty. A redeploy neither migrates nor swaps the database (confirmed: identical DB + content across the last three runs).
- Therefore the episodes were removed by an **application-level write at 14:05:05**, during normal runtime, not by the pipeline.

## Strong supporting signal (hypothesis for E1 to confirm)
There is a tight edit burst on 2026-10-24 at ~14:05: USF emptied at 14:05:05, then **Cosmic Bunny (14:05:23)** and **La Cité des Cieux (14:05:35)** were saved seconds later and **kept** their episodes. This looks like a save/update that writes back a *lightened* creation object (the one `_lighten` strips of episodes for list responses). If a save path ever persists a list-shaped / lightened payload, it overwrites `episodes` and `chapters` with `[]`. The user's note that "no code path deletes episodes" covers explicit deletes — but an update that writes back a lightened object is not a delete; it is an overwrite and would produce exactly this. **Recommend E1 audit the creation update/save endpoint** for writing back objects that have been through `_lighten`.

## Recoverability
- The live collection no longer holds the USF episodes, and there is **no in-DB backup** and **no alternate DB** that still contains them (all reachable runs point to the same DB with the same empty doc).
- Only recovery path is a **MongoDB Atlas backup / point-in-time restore to just before 2026-10-24T14:05:05 UTC**. That is Atlas-side and outside the deployer's tools — requires the user / Emergent support to perform an Atlas snapshot restore (ideally into a scratch DB/collection so current data is not overwritten).

## Not the cause (ruled out)
- DB_NAME / MONGO_URL change on deploy — NO (same across 3 runs).
- Data migration on redeploy — NO (redeploys don't migrate).
- Preview→prod confusion — data was authored in prod; preview has no USF, consistent.
